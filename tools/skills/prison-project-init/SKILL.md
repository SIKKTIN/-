# 《监狱风云》对话初始化

通过一次有选择的只读检查，让用户和新对话里的助手对同一份工程建立共同认识。输出中文项目简报，而不是只说“已了解”。

## 定位工程

- 首选用户指定的工程；本机常用位置为 `E:/Project/Godot/这次怎么逃`。用 `project.godot` 的项目名和场景入口确认身份，不因目录旧名改称另一个项目。
- 聊天可能从 `E:/Project/Taptap` 开始。该目录原先放网页原型，目前保留交付记录，不是 Godot 主工程。`E:/Docs/这次怎么逃` 是独立 GameCreator 文档工程。
- 路径失效时先在当前工作区查找 `project.godot`；只有找不到或存在多个无法区分的工程时，再询问用户。
- 遵循适用的 `AGENTS.md`。读取 [项目导航与历史线索](references/project-map.md)，用它定位文件，不把其中的日期性记录当成最新状态。

## 建立当前事实

先读 `project.godot`、`README.md`、`export_presets.cfg`，再按需要查看入口脚本、配置和最近的开发记录。通常先覆盖这些内容：

- **玩法和实现范围**：玩家角色、主地图、教程与时间规则、已接入的核心系统。计划里的功能和已存在的实现分开描述。
- **实际运行链路**：从 `run/main_scene` 追踪菜单、加载界面和游戏场景。文档与配置冲突时说明差异，以实际配置和调用链为准。
- **工程职责**：概括 `scripts/core`、`world`、`actors`、`presentation`、`ui`、`items`、`minigames`、`editor` 及 `data/art/audio/docs/qa/tools`。只列最有用的入口，避免复述所有目录。
- **当前工作与交付**：检查相关开发计划、性能报告、构建验证记录和 `build/android` 中实际存在的 APK。预设版本号不等于已生成该版本；磁盘上存在 APK 不等于手机安装或验证通过。
- **工作区状态**：用 Git 状态概括未提交改动的范围；必要时只查看相关差异。不要把整个脏工作区归为本助手所做的修改，也不要把未提交理解为未完成。

文件多时先用 `rg --files` 找位置。对大地图 JSON 提取地图 ID、边界、房间名和实体数量，不整份读入；对大报告优先读取 summary、checks、failed、scope 和构建信息。最近修改时间仅用于找候选证据，不能替代报告内容和版本对应关系。

进度结论标明依据：**当前代码可确认、已有测试报告、用户手工反馈、待验证**。尤其区分 Windows 性能采样、Android 包体/签名检查和 Android 真机实测；没有新设备数据时，不宣称已稳定 60 FPS。文件缺失或资料冲突时明确指出，不补写猜测。

## 向用户介绍

默认给出约一屏到两屏的简报，可按内容使用短段落或表格，覆盖：

1. 项目是什么、当前阶段和主工程路径。
2. 核心玩法与主要已实现系统。
3. 关键代码/资源入口，以及启动项目的方法。
4. 最近完成的工作、当前可用构建和已验证范围。
5. 尚未完成或待确认的问题，以及当前最值得接着做的一两件事。

给关键本地文件使用绝对路径 Markdown 链接。命令只展示适合当前工程的运行或构建入口，不展开完整工具链教程。若用户只要简短介绍，压缩篇幅但保留验证限制和待办。

## 执行边界

初始化本身不修改代码、不导入素材、不启动游戏、不打包、不跑整套测试、不安装到手机，也不向 GameCreator 或其他服务提交内容。可以读取已有结果和工具版本；用户同时要求后续操作时，完成简报后按其要求继续。

不要在初始化时扫描凭证文件、签名私钥或整份个人编辑器配置。普通游戏运行不需要 GameCreator 凭证。将本轮观察保持在对话上下文中；只有用户要求维护交接记录时才更新持久文档。
