# P15 · 手电视野、安全房间与近距离互动 · v0.6

按用户反馈及确认实现：

1. 原半透明警戒扇形替换为真实 PointLight2D 手电，120°、随位置/朝向，物体遮光；保留细轮廓指示实际检测边界。夜间155、白天210，均大于旧110；夜间光强.65，狱警身体只接收房间灯，避免被自己手电洗白。
2. 左侧起始房间安全：R01 x<508，R02 x<670。狱警的移动、寻路、发现、接触抓回受 guard_zone 限制；伙伴回房当次tick立即解除该目标追击。地面虚线标出边界，灯光也不越界。
3. N切换昼夜同步新的检测半径；目前不是按每个位置的像素亮度决定潜行概率。
4. 选中伙伴靠近可用目标时显示互动图标；点击或E聊天/撬锁/推箱。再次点击进行中的聊天/撬锁图标停止自己的操作；换人保持其他人操作。原右侧全局技能按钮隐藏，右键移动/接触推箱仍可用。

## 实际验证

`p15-guard-interaction-1280x720.json` 和 `p15-guard-interaction-960x540.json` 各50项通过，20张真实 Godot 截图覆盖双关昼/夜手电与聊天、锁门、箱子图标。确认 day 180距离可见而 night不可见、立即发现、回安全房间立即解追且不抓回、路径和整个人物占地不跨边界。

每关在60Hz逻辑步进运行60秒巡逻，R01 17 / R02 42次换点，全程在监管区。手电像素对照：安全房间增亮0，监管区地面增亮约.336–.352，证明确实打光并限制安全边界。初次像素探针落在不受灯光影响的朝向箭头上，修正到裸地面后重测通过。

图标测试确认真实技能条件、开始/停止、切人保留、开门隐藏、追击不能聊天、离开箱子隐藏和实际推箱；`p15-rts.json` 20项回归通过。组件测试通过Godot按钮pressed信号验证回调；随后在实时主干窗口向Viewport注入鼠标左键按下/松开，经真实GUI分发点击门旁图标，撬锁操作实际启动true，见`p15-gui-click.json`。自动注入输入不等于真人体验。

原生夜间完整路线：

- R01全撬锁：17.335秒三人逃脱、0抓回，`p15-live-r01.json`。
- R02聊天+撬锁+力量：15.939秒三人逃脱、0抓回，`p15-live-r02.json`（headless=false）。聊天者先到(730,340)，撬锁者经下方靠门；两人逃脱后聊天者退回(650,280)安全区，等狱警向下巡逻的空档，再走上门撤离。运行中AI持续推进，不暂停/搬动狱警。
- 旧R02路线扩大半径后抓回2次、门只开29.8%并超时，保留 `p15-r02-old-route-failure.json/png`。新路线探索也发现聊天者直接向上撤离会迎上追击，需要实际利用安全房间。这是新危险规则造成的策略变化，未通过调小半径或取消即时发现规避。

自动运行不等于真人趣味性；本轮未验证所有随机配置、白天完整路线与所有帧率。既有P13/P14证据保留，旧110范围及旧路线结论属于历史构建。原手绘PNG、独立碰撞与持续技能数值未改。
