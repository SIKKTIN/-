# P56 同源墙体瓦片

用户通过主美明确指出 A25 的转角、旧横墙和长竖墙不是同一风格，要求参考瓦片地图制作同材质、可重复拼接的组件。P56 完整替换 R04 食堂的相关表现，A24/A25 历史素材及交付证据保留。

## 同一母版、同一绘制接口

主美 A26 交付一个 1536×1024 RGB 原图 wall_tiles_master_v26.png。14 个组件全部从该图的墙顶、灰褐抹灰、暗灰墙脚三个区域采样，游戏内共用一个预生成 mipmap 的 GPU 纹理。石块单元 64，纹理周期 128；横墙 128×114、纵墙 24×128、转角 80×150、门柱 32×121.5、门楣 180×31.5，以及对应 20 厚的专用组件。门的金属主体仍使用原资源。

石材尺寸沿墙方向保持不变。20 厚组件只改变截面并裁对应源区，横臂仍长 80，避免将整块转角缩窄后产生另一种石块尺度。北墙顶 Y=1147.5，墙脚 Y=1261.5；转角结束 Y=1297.5，后续纵顶以同一顶点为周期原点，接出相位 22。横向组件使用相对 X=720 的 phase_shift，右角和厨房接点保持源纹理沿世界 X 正向连续。正尺寸 UV 支持 transpose、镜像、相位和任意末段裁切，不拉伸最后一块，也不产生新的 PNG。

scripts/presentation/wall_components.gd 是游戏和地图编辑器共用的组件绘制入口。WorldVolume 的墙体、门楣、普通组件摆件以及 MapCanvas 的摆件预览都使用同一组 assembly_patches，不会把全幅三段母版直接压进竖墙或转角。编辑器 14 个配套 MeshTexture 图标使用同源原生二维网格。

原有墙体、门洞、碰撞、日程、食堂 12–14 点开放和两小时禁闭/救援规则不变；运行 FPS 保留。测试使用临时未保存文档/运行对象摆放横墙、竖墙和 L 角，原地图 SHA 保持不变。

## 实际运行与验证

215/215 项检查通过，明细 docs/tests/p56-summary.json：1200×720 与 960×540 原生 GPU 窗口各 25 项，左右二倍相机与接点像素检查 8 项，门禁/禁闭回归 73 项，编辑器操作回归 78 项，原生编辑器及游戏摆件显示 6 项。主美另独立核对整体风格与实际近景，见 A26 的最终视觉记录。

普通摆件测试发现通用矩形接触阴影填进 L 角的空区域；程序按 assembly 覆盖范围排除不完整包围盒的这种假矩形阴影，H/V 完整矩形仍保留原阴影。修复后同一世界点 (1350,900) 在临时摆件加入前后像素完全一致，RGBA 都为 (0.6,0.6275,0.549,1)，不是放宽判定阈值或比较两个不同地坪点。

首次导入期间工具编辑器先引用尚未登记的母版 PNG，出现 14 条加载错误；重新导入后错误为零。主美隔离图标验证还发现二维顶点格式和临时资源引用生命周期问题，均在正式冻结前解决。资源加载成功不代替实际 GPU 图标可见性，最终原生调色板和编辑器截图已核对。
