# P79 追捕稳帧与帧率预设

已优化追捕、寻路和持续绘制，并在暂停菜单添加60帧、90帧和不限帧选项。默认60帧，选择自动保存到独立本地配置；切换不改变物理时钟、日程、角色速度、检测半径或抓捕条件。

## 修改与原因

- 碰撞和视线查询先从空间索引选取候选，再沿用原始精确检测；远距离寻路不再反复扫全场墙体。
- 网格使用单位权重的跳跃搜索和Octile估计；开关门只更新受影响的网格，直线路径先压缩再精确平滑。[Godot AStarGrid2D 文档](https://docs.godotengine.org/en/stable/classes/class_astargrid2d.html)。
- 看守复用安全路线，目标移动更新约每0.25秒一次，并错开重算；真正阻塞或状态改变仍立刻请求。复杂看守寻路超过本帧约1ms累计额度后，保留旧路线并在相邻帧重试；直达路线、视线检测、移动与接触抓捕不延后。
- 地面绘制提前覆盖摄像机周围256像素范围；小地图静态墙体留存命令；家具只在房间/门状态变化时同步。
- 墙影与门/箱子阴影分开，开关门不再重画全场墙影。灯光只更新变化的遮挡体并剔除不可影响当前屏幕的灯。
- 所有模式保持原有美术、光影、巡逻人数和AI检测规则。保留地图及共享目录中的外部未提交修改。

## 实测

原生1200×720、D3D12、RTX4050、同一R04地图。每个模式运行普通巡逻、寝室追捕、走廊移动、全员警戒、持续监工追捕、持续夜间追捕六种场景；每场7秒，前1.5秒暖机不纳入帧统计。持续追捕压力测试仅屏蔽终局捕获，以免一次抓捕后无法再测；正常抓捕与三次禁闭失败另行验收。

基线寻路最大29ms（普通巡逻）/81ms（夜间警戒），旧夜间警戒帧P99约96.6ms。最终夜间警戒在60模式帧P99约26.2ms，持续夜间追捕P99约16.85ms；完整数字保留于performance.json，包括偶发最长帧，不只报告均值。

60模式六组平均59.24–60.00FPS；90模式六组平均82.68–90.00FPS。60模式作为稳定优先的默认；90是目标上限，密集场景尚非全程锁90，不能承诺设备无关的固定帧率。

## 验证

26项性能/行为回归、53项屋顶遮挡回归、8组画面对照通过。包括1600条碰撞段和1600条视线与原始全场算法一致、140组跳跃寻路可达性与精确路径检查、门网格增量更新与全量结果一致、所有外围看守劳动抓捕、看门犬寻路、三次禁闭失败、暂停时切换90帧及配置保存、1200/960布局。

8组昼夜画面与旧地面/墙影/小地图绘制参考比较，至少99.87%像素完全相同，平均通道差小于0.0012/255；少量裁剪边界出现量化误差，未宣称逐字节完全相同。逐项容差与像素差统计见p79-visual-acceptance.json。

旧P75脚本仍硬编码遮挡功能加入前的NPC注册、苏醒速度假设，不纳入当前地图通过项。当前追捕/禁闭/遮挡规则由新用例直接验证。GameCreator服务两次CLI连接失败，已保留本地交付记录，未伪造远程验收。
