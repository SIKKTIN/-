# v0.8.2 跟随镜头稳定与帧同步

2026-10-05，用户反馈走动时镜头震动、画面看似撕裂。P25由制作人维护核心相机与主循环，本轮未改寻路/移动/碰撞、地图、美术PNG或用户project.godot的本机修改。

## 修复

游戏主循环改为人物/狱警移动 → Camera2D一次tick → 表现和屏幕交互图标刷新。相机不再有独立的脚本_process，使用idle回调与同一实际canvas变换，避免HUD互动图标投影在上一帧镜头位置，而场景已经滚动到新位置。原生连续12帧检查拾取图标与当前渲染相机匹配。

跟随由端点指数插值改为对本帧线性移动目标的解析积分。固定速度时长期跟随距离为v/10，避免短帧与长帧给出不同滞后。切人、拖图、定位/暂停/失焦后重置采样；静止时小于0.001单位残余直接归零。边界、HUD固定、小图全图、无边缘滚屏以及独立命令保留。

P24在手指/左键按住期间停止跟随，会使连续点击产生停走。现在非拖动轻点期间继续跟随，按下时保存世界投影变换，松开时用该变换确定目标；实际拖动达到12单位后暂停跟随，松开不下令。重新选人、定位/F继续恢复。验证含0.18秒按住期间镜头连续移动与正确世界目标。

## 检查与排除项

初检把Viewport与CanvasItem纹理枚举混淆，误认为最近邻。两者不同：Viewport LINEAR=1、CanvasItem LINEAR=2；实际原视口已线性采样，VSYNC也已开启。通过17个分数像素镜头步进、同一冻结R04地板补丁的渲染对照，确认显式切换根节点线性采样不改变画面，撤销该无效改动。最终保留原采样与垂直同步，不把采样改动当作有效修复，不凭截图宣称物理显示扫描撕裂消除。

p25-sampling-before/after.json：线性目标(220,40)单位/秒，模拟30/55/90/165Hz交替dt，稳定阶段跟随距离最大波动0.183497→0.000140537世界单位；新平均滞后(22,4)符合解析结果。此为相机数学夹具，不冒充人物碰撞或完整游戏路线；静态纹理的时间变化指标保持相同。PNG与canvas_x记录实际原生帧缓冲。

p25-native-follow-1280x720.json及960x540.json：各25项实际原生帧/持续游戏AI检查通过，包含30次Viewport右键、30次跨帧ScreenTouch、选中/换人跟随、拖动暂停/小地图查看/定位恢复、按住轻点不断镜头、最新目标到达、HUD固定、小房间、当前帧图标投影、单一相机更新及VSYNC开启，共50项。右键帧等待P95约8.785/7.982ms；仅Windows本机样本。未Android/iOS真机或真人体验复核。

保留p25-follow-initial-threshold.json：旧原生检查要求滞后<25，解析模型260/10=26，修正测试为v/10+3并实测通过。保留p25-native-960-initial-failure.json：一次960原生运行多项输入/跟随失败，同代码再次独立运行25项通过；缺少当次焦点记录，未断言具体原因或修改系统来掩盖失败。

实际编辑器正常随机R04从出生下达移动，记录120真实渲染帧的伙伴/相机/canvas位置，当前运行无游戏错误：p25-live-follow.json/.png。源与证据哈希见p25-build.json。尚不能用这些技术证据代替用户对屏幕显示效果的复核。
