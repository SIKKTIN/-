# 编辑器图标长期美术交付规范

用户于2026-10-06明确要求：今后制作场景美术，必须同时交付对应地图编辑器图标。本规范是主美后续每项新摆设、角色与交互物任务的必备交付/验收条款，由制作人将制作方案写入GameCreator正式模块；本文件不自行修改正式模块或发布新的视觉基线。

## 每项资产同时交付

1. 可在游戏中使用的世界资源及其已约定ID、尺寸、裁区、锚点/脚印。
2. 单独可加载的编辑器Texture2D资源路径 `editor_icon`，例如 `res://art/editor/v01/icons/bunk_bed.tres`。禁止填世界PNG路径后依赖编辑器猜裁区，禁止将文件名或内部ID绘入图标。
3. ID、中文显示名、分类、世界资源→编辑器图标映射与源引用记录。摆设ID必须逐字等于原世界asset_id；本轮分类固定furniture/cafeteria/props。新增分类由制作人与编辑器接口确认，不能因交付图片擅改类别枚举。
4. 48×48和64×64固定显示框的真实Godot联系表、资源加载/透明/源文件检查结果；美术本人实际查看后提交待验收，由指定负责人审核，再由制作人接入复核。

本轮编辑器独立清单为 `art/editor/v01/manifest.json`：

```json
{
  "schema": 1,
  "assets": [{"id":"bunk_bed","name":"双层床","category":"furniture","editor_icon":"res://art/editor/v01/icons/bunk_bed.tres"}],
  "tools": [{"id":"meal","name":"取餐点","icon":"res://art/editor/v01/icons/meal.svg"}]
}
```

后续交付应提供同样准确的editor_icon字段，或按该独立清单补齐新项；程序负责人决定将字段写入世界manifest还是独立清单。主美不能越过任务归属修改旧manifest/程序，需给出可直接应用的映射。

## 外观与逻辑标记分开

家具/场景物优先AtlasTexture引用已验收PNG，裁去背景与冗余透明区，不改原像素。细长物可选能够辨认的代表性局部，例如锁门锁闩；交付记录裁区，不能从缩略图推导碰撞或世界尺寸。

开门外观、锁门外观均是摆设缩略图，不代表真实开门/上锁操作，也不启用主锁门规则。真实主规则门使用独立 `door`符号；寝室规则门使用 `dorm_doors`。不要让美术外观卡与规则点共享未注明的ID。

人物/物品放置、工作/取餐/用餐/活动点、区域/范围、巡逻路径等使用专用符号，而不是把工作桌、餐盘、围栏当作逻辑点。符号示例：work锤子、meal餐罩、dine餐具、free活动人物、zones虚线范围、patrol路线、dormitories寝室范围。当前角色放置工具的ID取地图实际组键（starts、guard_start、gate_guards、merchants），物品符号按定义键（door_key、lock_tool、scrap）映射；未来新角色/物品还需记录其稳定世界定义ID、形象来源及放置工具ID的对应关系，不能只按当前运行角色序号猜测。外形资源与逻辑工具可以复用图标，但每条映射必须明确。

显示eye与锁定lock是编辑器图层操作符号，不绘入世界，不替代门状态图标。图标含义须在name/tooltip给人类可读名称，小尺寸不靠内部ID解释。

## 尺寸、透明与风格

- 图标显示框固定48/64；图像保持比例并居中，保留约4–6%的透明安全边距。AtlasTexture可用margin建立虚拟正方形，禁止把世界素材压扁来凑正方形。
- SVG建议64×64 viewBox，透明背景，深墨色#303b46、青绿#328b82、少量赭黄#c69c5e；64画布线宽约3–4。奶油纸卡背景由编辑器Theme提供，不烘焙进图标。
- 小尺寸保留主轮廓；避免细密文字、依赖颜色的单独区分、假棋盘透明、白/黑底块和场景地板。宽台/细栏可保持整体轮廓，识别细节不足时做代表性裁区或单独符号，并经实际48px查看确认。
- 编辑器图标不得携带世界world_size/碰撞信息来驱动显示大小。TextureRect先设EXPAND_IGNORE_SIZE再赋纹理，再设48/64尺寸与STRETCH_KEEP_ASPECT_CENTERED；Button图标要限制icon_max_width及expand_icon。不能将Atlas的原始尺寸作为控件最小尺寸，不能把64画布当64世界单位。

## QA与验收记录

必须检查ID唯一、世界ID覆盖率100%、分类/映射正确、所有路径实际加载为Texture2D、裁区在源图内、不混入邻物、源PNG不被改写、虚拟显示框透明且48/64可辨认。AtlasTexture.get_image()可能只返回源裁区、不含虚拟margin；透明边检查应在透明SubViewport实际绘制图标后采样，不能把局部锁闩贴边误判成背景不透明。

PNG生成/修改必须使用项目适用imagegen流程；代码原生SVG/AtlasTexture不需要额外生成位图。每项图标保留来源、完整生成prompt（如果生成）、尺寸、裁区/虚拟margin、源哈希或矢量作者信息以及QA路径。复用旧PNG仍要做缩小QA，不能只宣称“已验收的原图所以图标通过”。

任务workScope/acceptance必须写入“世界资源+editor_icon+映射清单+48/64真实加载/审图证据同时交付”。缺少图标或映射则不算美术交付齐全；主美提交待验收，制作人接入后核对真实卡片显示、分类/图层行为，资源验收与程序功能验收分别记录。
